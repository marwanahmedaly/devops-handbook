# DevOps Learning Handbook

A small, hands-on handbook of DevOps notes, written by learners as they study. It also doubles as a safe place to practice Git workflows (branches, pull requests and reverts).

## Contents

| Topic | File | Status |
|---|---|---|
| Linux | [linux-notes.md](linux-notes.md) | Started: kernel and distributions |
| Git | [git-notes.md](git-notes.md) | Started: staging and commits |

More topics will be added as they are learned (for example shell, networking, containers, CI/CD and infrastructure as code).

## How to contribute

1. Create a branch for your topic.
2. Add or edit a Markdown note. Keep notes short, practical and in your own words.
3. Open a pull request and describe what you learned.

Draft work goes in a `drafts/` folder, which is ignored by Git, along with `*.log` and `.env` files.

## Goals

- Practice writing clear technical notes.
- Practice Git collaboration: branching, commits, pull requests and reverts.
- Build a reference that grows with each topic.
